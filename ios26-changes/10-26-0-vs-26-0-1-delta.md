# Дельта 26.0 → 26.0.1 детально

Финальная глава раздела iOS 26 changes. Расширенная версия главы VII.3 — что реально меняется между 26.0 и 26.0.1 с точки зрения автора твика.

## 1. Общий паттерн минорных обновлений Apple

Minor release (`.0 → .0.1` или `.0 → .1`) обычно содержит:

- **Security fixes** (чаще всего).
- **Bug fixes** (crash reports, которые Apple собрала).
- **Minor UI tweaks** (локализация, редкие визуальные правки).
- **НЕ** содержит: новых публичных API (это к `.0`, `.1.0`).

Для автора твика это означает: **ваш twик на 26.0 с большой вероятностью работает на 26.0.1 без изменений**. Нужна верификация, но не ожидайте расхождений.

## 2. Конкретные билды

Из `BaseBin/_external` и `Info.plist` эксплойтов (глава V.3, VII.3):

- `23B5044l` — one of 26.0 builds
- `23B5059e` — one of 26.0 builds (возможно RC)
- `23B5064e` — 26.0.1 (возможно)

Проверка на устройстве:

```bash
ssh mobile@<ip>
sysctl -n kern.osproductversion    # 26.0 / 26.0.1
sysctl -n kern.osversion            # 23B5...
```

Dopamine support — все эти билды (глава I.5).

## 3. Что Apple фиксит в security

Публично — через `support.apple.com/<HT>`. Обычно включает:

- CVE в WebKit (патчи для JavaScript engine).
- CVE в ядре (память, race conditions).
- CVE в различных frameworks.

Для jailbreak-эксплойтов это **потенциальная угроза**: один из CVE может быть тем, что DarkSword/ClearSword использует.

Если Apple закрывает уязвимость — Dopamine на этой версии **перестаёт работать**. Проект реагирует через update.

На момент написания книги — проект декларирует поддержку обоих 26.0 и 26.0.1. Это значит, что текущие эксплойты DarkSword/ClearSword работают на обеих.

## 4. Что меняется для автора твика

Концепция:

| Зона | Вероятность изменений 26.0 → 26.0.1 |
|---|---|
| Public UIKit/Foundation API | Очень низкая |
| Private SpringBoard классы | Низкая (name stability > minor) |
| Private UIKit internals | Низкая |
| Private xpc service names | Очень низкая |
| Entitlement requirements | Низкая |
| Codesign checks | Низкая (но Apple может усилить) |
| Jailbreak-targeted mitigations | Средняя (Apple может закрыть эксплойт) |

Для подавляющего большинства tweak workflows — ничего не меняется.

## 5. Чеклист миграции 26.0 → 26.0.1

```
[ ] Dopamine поддерживает 26.0.1 — проверить `DOEnvironmentManager.m:254`
[ ] Устройство обновлено на 26.0.1
[ ] Dopamine переустановлен и активирован
[ ] Твик переустановлен (возможно, с переcборкой)
[ ] Логика unit tests проходит (локально, не на устройстве)
[ ] Твик загружается в целевом процессе
[ ] Основной сценарий работает
[ ] Edge cases проверены
[ ] Нет новых crash reports
[ ] Если расхождения — задокументированы в CHANGELOG
```

Обычно весь чеклист проходит за 10-15 минут.

## 6. Если что-то сломалось

Иерархия причин:

1. **Dopamine не поддерживает 26.0.1** — проверить проект (мало вероятно, но возможно).
2. **TweakLoader не грузится** — проверить `/var/jb/usr/lib/TweakLoader.dylib` + `ellekit` package.
3. **Private класс переименован** — probe (глава V.2).
4. **Private метод переименован** — то же.
5. **Entitlement изменился** — ldid -e, сравнить с 26.0.

## 7. Условный код для 26.0 vs 26.0.1

Из главы VII.3:

```c
#include <sys/sysctl.h>

static NSString *gIOSVersion = nil;

static void detect_version(void) {
    char buf[64] = {0};
    size_t sz = sizeof(buf);
    if (sysctlbyname("kern.osproductversion", buf, &sz, NULL, 0) == 0) {
        gIOSVersion = @(buf);
    }
}

static BOOL is_26_0_1_or_later(void) {
    if (!gIOSVersion) return NO;
    return [gIOSVersion compare:@"26.0.1" options:NSNumericSearch] != NSOrderedAscending;
}

%ctor { detect_version(); }
```

Используется редко, но при необходимости — вот паттерн.

## 8. Автотест на обеих версиях

Если у вас 2 устройства:

```bash
# Для каждого устройства:
DEVICE_26_0="192.168.1.100"
DEVICE_26_0_1="192.168.1.101"

for DEV in $DEVICE_26_0 $DEVICE_26_0_1; do
    scp packages/*.deb mobile@$DEV:/tmp/
    ssh mobile@$DEV "sudo dpkg -i /tmp/*.deb && killall -9 TestbedApp"
    # Автоматизировать сценарий (например, через mobdeagent, если такое есть)
    # ...
    # Собрать log:
    log stream --device <udid-of-$DEV> \
        --predicate 'subsystem == "com.example.mytweak"' \
        --timeout 30 > log-$DEV.txt
done

diff log-$DEVICE_26_0.txt log-$DEVICE_26_0_1.txt
# Если diff пустой — 100% совместимость.
```

## 9. Что заявляет Apple

Для 26.0.1 (как и любой minor):

- Changelog в Settings → General → About.
- Detail — на `support.apple.com/HT<id>` (ищется по номеру iOS).
- Security Content — отдельная страница.

Автору твика стоит читать Security Content — там CVE, которые могут касаться вашего кода (например, если ваш твик использовал WebKit-based component, closed CVE может означать fix в фреймворке).

## 10. История проекта Dopamine на этой паре версий

Из коммитов проекта:

- **24ea745** — «add roothide support for Dopamine 3» (base).
- **79a4579** — «Restore 26.0b1 support by changing range minimum of ClearSword/DarkSword to 19.0».
- **96ab178** — «Fix some offsets on iOS 26.5+» (намёк на то, что проект активно работает над новыми iOS).

Коммиты показывают: проект **активно** реагирует на новые Apple релизы. 26.0 и 26.0.1 оба поддерживаются; будущие minor могут потребовать обновления Dopamine.

## 11. Что подтверждено

- **Подтверждено исходниками**: билды `23B5044l`, `23B5059e`, `23B5064e` явно поддержанные (Info.plist эксплойтов DarkSword/ClearSword, глава I.5).
- **Подтверждено**: `sysctlbyname("kern.osproductversion", ...)` работает для определения версии.
- **Требует проверки**: конкретные CVE, закрытые в 26.0.1 — читать Apple security content.
- **Не подтверждено** (намеренно): влияние конкретных CVE на jailbreak-эксплойты — проект сам может пояснить в своём changelog.

## 12. Выводы

Главный тезис: **26.0 → 26.0.1 для автора твика — обычно non-event**. Public API стабильно, private — почти стабильно. Dopamine декларирует обе версии.

Процедура обновления:

1. Прочитать Apple release notes 26.0.1.
2. Если жrt security fix в WebKit/kernel — проверить, что Dopamine всё ещё поддерживает.
3. Если да — обновить устройство, Dopamine, твик.
4. Пробежать по чеклисту (раздел 5).
5. Если все OK — релиз 1.0.1 вашего твика с заметкой «26.0.1 verified».

Это стандартный minor-update workflow.
