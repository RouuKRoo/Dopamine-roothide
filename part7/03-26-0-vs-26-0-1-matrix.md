# Глава VII.3. Матрица отличий iOS 26.0 vs 26.0.1 для авторов твиков

Финальная глава основной книги. Задача — зафиксировать то, что мы знаем о различиях между двумя целевыми версиями, и дать процедуру верификации вашего твика на обеих.

## 1. Что подтверждено о поддержке

Эта глава опирается на прямые цитаты из репозитория:

**1.1.** `Application/Dopamine/Jailbreak/DOEnvironmentManager.m:254`:

```objc
if (cpuFamily == CPUFAMILY_ARM_VORTEX_TEMPEST ||
    cpuFamily == CPUFAMILY_ARM_LIGHTNING_THUNDER) {
    return @"iOS 15.0 - 18.7.1, 26.0 - 26.0.1 (A12/A13, PPL)";
}
```

**1.2.** `Application/Dopamine/Exploits/DarkSword/Info.plist` (и `ClearSword/Info.plist`):

```xml
<key>DPSupportedRanges</key>
<array>
    <dict>
        <key>End</key>
        <string>18.7.1</string>
        <key>Start</key>
        <string>15.0</string>
    </dict>
    <dict>
        <key>End</key>
        <string>26.0.1</string>
        <key>Start</key>
        <string>19.0</string>
    </dict>
</array>
<key>DPSupportInclude</key>
<array>
    <dict>
        <key>Builds</key>
        <array>
            <string>23B5044l</string>
            <string>23B5059e</string>
            <string>23B5064e</string>
        </array>
    </dict>
</array>
```

Что это означает:

- Диапазон 19.0–26.0.1 покрывает iOS 26.0 и 26.0.1 (внутренний Apple-номер iOS 19 — это то, что потребители видят как iOS 26).
- Явные билды: `23B5044l`, `23B5059e`, `23B5064e`. Эти билды — конкретные beta/GM-пакеты iOS 26.0/26.0.1.
- Для A12/A13 (Vortex-Tempest / Lightning-Thunder) оба диапазона работают.

## 2. Чего мы НЕ знаем из репозитория

Проект не содержит прямых сведений о:

- Что именно изменила Apple между 26.0 и 26.0.1 — для этого нужны Apple release notes и security notes.
- Какие private селекторы переименованы.
- Какие entitlements закрыты.

Это — задача исследования на устройстве. Эта глава даёт процедуру.

## 3. Публичные источники о дельте 26.0 → 26.0.1

Apple публикует два вида notes:

- **Release notes** — крупные изменения API. Доступно на `developer.apple.com/documentation/<framework>/<ver>-release-notes/`.
- **Security notes** — CVE и security fixes. На `support.apple.com/HT<id>`.

Это **первичные источники**, которые я советую проверить читателю, не копируя их в книгу (чтобы не пересказывать то, что меняется).

Главное наблюдение: минорные версии (26.0 → 26.0.1) обычно содержат security fixes и bug fixes, редко — изменения API. Для автора твика это значит:

- Публичные классы и методы **почти всегда** стабильны.
- Private классы и методы — **могут** быть переименованы, но реже чем между major версиями.
- Эксплойты jailbreak — могут закрыться, но **в нашем случае** DarkSword/ClearSword работают на обеих (подтверждено Info.plist).

## 4. Шаблон проверки своего твика

Самое важное — не предполагать. Запустить тест на обеих версиях.

### 4.1. Если у вас два устройства

**Устройство A** на iOS 26.0, **устройство B** на iOS 26.0.1.

```bash
# Для каждого:
scp packages/*.deb mobile@<ip-A>:/tmp/
ssh mobile@<ip-A> "sudo dpkg -i /tmp/*.deb && killall -9 TargetApp"
# ... тестирование сценариев ...
# Записать результаты

# То же для B:
scp packages/*.deb mobile@<ip-B>:/tmp/
ssh mobile@<ip-B> "sudo dpkg -i /tmp/*.deb && killall -9 TargetApp"
# ... тестирование ...

# Сравнить логи
```

### 4.2. Если у вас одно устройство

Два варианта:

**А. Обновление в процессе теста**:

1. Жbroken устройство на 26.0.
2. Тестируете твик.
3. Удаляете jailbreak, обновляете iOS до 26.0.1.
4. Переустанавливаете Dopamine (на 26.0.1).
5. Переустанавливаете твик.
6. Повторяете тесты.

Это ломает устройство между этапами, но даёт конкретный тест.

**Б. Виртуализация (ограниченно)**:

На macOS Sequoia есть `virtualization.framework`, но iOS там не запускается полноценно. Этот путь — не для нашей задачи.

## 5. Чеклист миграции 26.0 → 26.0.1

При обновлении Apple с 26.0 на 26.0.1 ваш твик может:

1. **Работать идентично** — наиболее частый сценарий.
2. **Работать, но с косметическими отличиями** — например, цвет/размер UI-элемента немного другой.
3. **Не загружаться** — класс private переименован.
4. **Загружаться, но хук не ловит** — метод private переименован.
5. **Крэшить** — API изменился в несовместимом направлении.

Пробегайтесь по сценариям:

```
[ ] Твик собирается с тем же Makefile/control
[ ] Dpkg -i проходит без ошибок
[ ] %ctor выполняется (лог «loaded» виден)
[ ] Хуки на публичные классы работают (протестировано)
[ ] Хуки на private классы работают (протестировано на устройстве 26.0.1)
[ ] Нет новых крэшей в .ips
[ ] UI отображается корректно
[ ] Settings работают корректно
[ ] Darwin notifications работают
[ ] Deinstall проходит чисто (prerm/postrm)
```

Если какой-то пункт отвалился — нужен условный код (глава V.5, раздел 8.3).

## 6. Условный код по версии

### 6.1. Через `kern.osproductversion`

```c
#include <sys/sysctl.h>

static NSString *gIOSVersion = nil;

static void detect_version(void) {
    char buf[64] = {0};
    size_t sz = sizeof(buf);
    if (sysctlbyname("kern.osproductversion", buf, &sz, NULL, 0) == 0) {
        gIOSVersion = @(buf);
    }
}

static BOOL is_at_least_26_0_1(void) {
    if (!gIOSVersion) return NO;
    return [gIOSVersion compare:@"26.0.1" options:NSNumericSearch] != NSOrderedAscending;
}

%ctor { detect_version(); }

%hook SomeClass
- (void)someMethod {
    if (is_at_least_26_0_1()) {
        // ветка для 26.0.1 и позже
    } else {
        // ветка для 26.0 и раньше
    }
    %orig;
}
%end
```

### 6.2. Через feature detection

Лучшая практика — не проверять версию, а наличие функциональности:

```objc
%ctor {
    Class newClass = NSClassFromString(@"_SBUINewClassInLatestVersion");
    if (newClass) {
        // есть новый класс — используем его
        %init(NewClassGroup);
    } else {
        // старый подход
        %init(OldClassGroup);
    }
}

%group OldClassGroup
%hook OldClassName
- (void)oldMethod { /*...*/ %orig; }
%end
%end

%group NewClassGroup
%hook NewClassName
- (void)newMethod { /*...*/ %orig; }
%end
%end
```

### 6.3. Через `respondsToSelector:`

```objc
%hook SomeClass
- (void)someMethod {
    if ([self respondsToSelector:@selector(newMethodIntroducedIn26_0_1)]) {
        [self newMethodIntroducedIn26_0_1];
    } else {
        [self fallbackMethod];
    }
    %orig;
}
%end
```

## 7. Build на 26.0 для совместимости с 26.0.1

Общее правило: собирайте твик с **минимальным** SDK, который даёт нужные API. Для нашей цели (iOS 26.0 на A13) — SDK 16.0 или выше, с `-miphoneos-version-min=15.0`.

Twic, собранный с таким SDK:

- Запустится на 15.0+ (где поддерживается).
- Использует стабильные публичные API.
- Не зависит от «новых» API iOS 26.

Это даёт обратную совместимость; твик, работающий на iOS 26.0, вероятно работает и на 26.0.1 — если он не использовал нестабильные private селекторы.

## 8. Deployment target vs runtime version

В Makefile:

```make
TARGET := iphone:clang:latest:15.0
# ^-- вторая часть "latest" — SDK; третья "15.0" — min version
```

- SDK **latest** — для компиляции, доступны все API вплоть до SDK версии.
- Min version **15.0** — твик загружается на iOS 15.0+.
- Если ваш код использует API, появившееся в iOS 17 — проверяйте `@available(iOS 17, *)` или `__builtin_available(iOS 17.0, *)`.

Пример:

```objc
if (__builtin_available(iOS 17.0, *)) {
    // iOS 17+ код
} else {
    // fallback для iOS 15-16
}
```

Это позволяет **один** `.deb` работать на всех версиях.

## 9. Знаем конкретно про поддержку эксплойтов

Из `Info.plist` DarkSword и ClearSword (глава I.5):

- Диапазон 19.0–26.0.1 покрыт.
- Явные билды: `23B5044l`, `23B5059e`, `23B5064e`.

Что это означает практически:

- На любом iPhone 11 / 11 Pro / 11 Pro Max / SE 2nd gen (A13) с одним из указанных билдов — Dopamine должен запуститься.
- Для билда 26.0.1 конкретно — в DPSupportInclude значатся его публичные билды.

Если ваш билд **не в списке** `DPSupportInclude`:

- Если он в диапазоне 19.0–26.0.1 — Dopamine попробует, но без гарантии.
- Если он вне диапазона — Dopamine откажет.

Проверка на устройстве:

```bash
sysctl -n kern.osproductversion    # 26.0 / 26.0.1
sysctl -n kern.osversion           # 23B5044l / 23B5059e / 23B5064e
sysctl -n hw.model                 # например iPhone12,1
```

## 10. Что меняется между минорными — наблюдаемые категории

Это — общая картина, не конкретика к 26.0.1 (её нужно получить на устройстве):

| Категория | Вероятность изменений в minor | Пример |
|---|---|---|
| Публичные API UIKit/Foundation | Низкая | обычно стабильны |
| Селекторы SpringBoard private | Средняя | переименование class/method между 26.0 и 26.0.1 возможно |
| Entitlements | Низкая | редко закрываются |
| XPC-протоколы | Низкая | обычно стабильны |
| Поведение lightning subsystems | Средняя | может перестраиваться |
| Jetsam limits | Низкая | обычно стабильны |
| CoreFoundation version | Низкая | small bump может быть |
| Dyld shared cache paths | Низкая | стабильно |

Для автора твика — главное checking что ваши конкретные хуки работают после обновления.

## 11. Что проверять после обновления Apple iOS

Если Apple выпустила 26.0.2, 26.1 или ещё дальше (вне заявленной Dopamine поддержки):

1. **Поддерживает ли Dopamine новый билд?** — Проверьте update Dopamine, прочитайте changelog, или `Info.plist` эксплойтов.
2. **Если нет** — не обновляйте устройство. Jailbreak может сломаться.
3. **Если да** — обновите Dopamine, затем iOS, затем переустановите твики, проверьте их.

Для **авторов твиков** — следите за Dopamine release notes. Если Dopamine добавит поддержку 26.0.2 — ваш твик нужно будет проверить.

## 12. Процедура «безопасного» обновления устройства

Если вы критически зависите от jailbreak и хотите minimize риск:

### 12.1. Шаги

1. **Бэкап**: iTunes/Finder encrypted backup до обновления.
2. **Текущая версия Dopamine** — убедиться, что для вас это рабочая версия.
3. **Проверить changelog** на предмет новой версии iOS.
4. **Не ставить обновление** без проверки: сначала наблюдать за community reports.
5. **При обновлении**: обновиться, затем переустановить Dopamine с нуля.
6. **Проверить** свои твики по чеклисту (раздел 5).

### 12.2. Что иметь на всякий случай

- Backup данных приложений (TrollStore + ваше тестовое приложение иногда помогают).
- Backup `.deb` файлов ваших твиков.
- Backup исходников всех твиков.
- Backup settings `.plist` файлов (в бэкапе Apple они есть, но проще отдельно).

## 16. Выводы

Главный тезис: **минорное обновление iOS (26.0 → 26.0.1) редко ломает публичное API; но private селекторы могут переименоваться**. Чек ваших твиков — обязательный, но обычно безболезненный.

Три якорных правила:

1. **Хукайте публичное API** где возможно. Оно стабильно между минорными версиями.
2. **Для private — defensive code**: `NSClassFromString`, `respondsToSelector:`, `%init(... = cls)`.
3. **Тестируйте на обеих версиях** перед релизом публичного твика.
